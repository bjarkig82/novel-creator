# Novel Creator 0.7.2

**Status: unpublished candidate.** The previous published package is
[0.7.1](0.7.1.md), published 2026-11-10. Release qualification, public artifact
verification and the annotated `v0.7.2` tag remain pending. No publication date
is assigned to this candidate.

## Changes from 0.7.1

`$novel-clarify` now normally offers 2–4 concise labeled answers with each
substantive question, plus **Custom — type your own answer**. Reply with a label,
adapt a suggestion, or type a different answer directly without selecting Custom
first. For example, “A: To protect someone” and “B: To protect herself” can be
answered with “Neither. She wants time to verify it.” The suggestions follow the
known story; fewer are offered when additional choices would be padding.

This applies to both legacy novels and Markdown notebooks. You can still request
fewer or no suggestions, remain unsure, skip, defer or stop. Nothing is selected
automatically. Clear selections establish only their identified proposition;
other suggestions remain provisional. Clarification still asks one question at
a time, defaults to at most five questions per pass, preserves each format's
save and history rules, and never rewrites manuscript prose.

Plain chat supports labels and custom text without a special widget or plan mode.
Optional native widgets must preserve custom input. Questions, suggestions and
the custom invitation follow the conversation language.

## Installation and project availability

After publication, install the exact version in your configured environment
outside the novel. This command is not a claim that the candidate is on PyPI:

```text
python -m pip install --upgrade novel-creator==0.7.2
```

A package installation alone leaves existing project-local guidance unchanged.
See the complete [project upgrade procedure](../upgrading-projects.md) before
writing with the new behavior.

| Project | How the 0.7.2 guidance becomes available |
| --- | --- |
| New legacy novel | Initialize using the 0.7.2 installation; its pinned legacy clarify skill and workflow include suggestions and custom answers. |
| Existing legacy novel | Preview and explicitly apply the published 0.7.2 framework update with the external controller, then reload project instructions and skills. |
| New Markdown notebook | Initialize using 0.7.2; the installed notebook clarify skill and workflow include the change. |
| Existing Markdown notebook | Preview and explicitly apply `novel-creator notebook update`, then reload project instructions and skills. Missing focused resources are added; unchanged original published 0.7.0/0.7.1 clarify resources can be replaced. |

The notebook update recognizes those original clarify files by frozen ownership
hashes, normalizing LF/CRLF for comparison. It does not treat arbitrary differing
files as framework-owned. Customized clarify files and other differing focused
resources block the update before application; inspect and resolve the reported
conflict without discarding custom work, then take a fresh preview.

Notebook updates preserve story notes, manuscripts, custom instructions, existing
history and unrelated staging. They do not stage, commit or push. Review the
framework diff and checkpoint exact changed paths yourself. Legacy updates retain
their dedicated framework commit and recovery protocol. Neither path converts
story formats or updates a real novel without an explicit reviewed application.

## Validation and limits

Full Linux qualification, source-bound Windows qualification, exact wheel/source
installation checks and prior-published-project update probes are required before
publication. Results are pending for this candidate; source guidance and focused
resource tests do not establish those release gates passed.

Updates bind the selected content and HEAD to a preview. Stale previews, unsafe
paths and customized resources are refused. An interrupted notebook update can
leave completed additions or replacements; preserve them, inspect partial files,
and take a fresh preview to finish the remaining work. A partially written or
customized conflicting file is not silently overwritten. Verify installed skill
files and linked guidance before reloading Codex.

Native Codex Desktop discovery, widget behavior, English/Icelandic literary
quality and voice timing remain separate host checks. Automated file and package
checks cannot establish what a writer saw or accepted.
