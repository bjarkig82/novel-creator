# Novel Creator 0.10.2

Status: **unpublished development candidate**, compared with published
[0.10.1](0.10.1.md). This feature preparation is not release qualification or
publication. Published installation guidance remains pinned to 0.10.1.

The candidate adds a focused side-character profile workflow for legacy novels
and format-1 notebooks. It asks up to three missing basics one at a time and
offers a complete provisional profile. In notebooks, intake, drafting and revisions
stay in chat until clear save approval. Legacy novels retain sourced capture of
the discussion and proposed profile; proposal capture does not accept it as canon.
Accepted profile content follows the selected format's existing identity,
provenance and save rules. Existing Character and
Character Development entry points remain available.

New setup includes the skill, linked workflow and bounded root routing. Existing
projects keep their pinned resources when Python is upgraded. The default Codex
project-skill notebook updater explicitly previews/applies the new resources and
root section, refreshing only verified shipped Help snapshots. Customized
resources, routing, redirected paths and stale previews refuse safely. Preview
binding includes inspected inputs, Git HEAD and exact index bytes; ordinary
preexisting staging stays intact. Other supported Codex/Claude Code/both
project/plugin notebooks use the separate feature-only maintenance helper;
it preserves integration markers and existing Help/shared workflows/roles,
adds the rendered workflow/project skill and appends protected root routing.
Plugin books require the matching updated/enabled plugin and receive no duplicate
local skills. Explicit conflicting writer rules require manual reconciliation.
See the complete [side-character upgrade sequence](../side-characters.md#install-or-update-the-unpublished-candidate).

After publication only, install the candidate's exact version using Python 3.11+:

```text
python -m pip install --upgrade novel-creator==0.10.2
```

After publication, preview/apply the explicit legacy framework update or the applicable
notebook resource update, review the resulting resource diff and reopen/reload
the project instructions and skills in Codex. Package installation alone is not
a project update. No real novel is rewritten by package installation. Existing
stories, custom instructions, history and unrelated staging must be preserved;
there is no format conversion. Native host skill discovery and subjective
profile quality require host observation and are not established by structural
tests. Current source/local artifacts can initialize disposable new books and
update notebook resources now; the ordinary existing-legacy updater requires a
published target. Offline candidate legacy tests use fixture transport rather
than bypassing public discovery. Full Linux qualification, the required Windows
release profile, complete release verification, release evidence, publication
and release tagging remain pending.

Focused Windows checks verified the previous-public notebook host/source/language
matrix, read-only previews, narrow additions, stale/custom/redirected-path
refusals and partial resume. Both locally built wheel and source distribution
were installed in isolated temporary environments and exercised new legacy and
notebook setup, default/nondefault notebook updates and offline fixture-driven
0.10.1-to-0.10.2 legacy updates. Story, history, custom instructions and unrelated
staging were preserved in these synthetic cases. Source and plugin archives
contain the new skill; these targeted results are not full release qualification.
