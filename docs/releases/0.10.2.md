Status: **UNPUBLISHED CANDIDATE**, compared with published [0.10.1](0.10.1.md).
Version 0.10.2 is not yet a verified PyPI release. Published installation
guidance remains pinned to 0.10.1. Full Linux qualification, the source-bound

## Changes since 0.10.1

### Author-approved session issue retrospectives

The candidate restores a retrospective entry for both formats, with local
session review and optional GitHub issues in **bjarkig82/novel-creator**. It
replaces the old automatic fix/branch/push/PR contribution lane. An explicit
retrospective or `$novel-retro` can review available evidence. Optional automatic
review requires a separate explicit author opt-in for the active writing session
and runs only at explicit session closure. Routine replies, saves and completed
deliverables do not trigger it. There is no background scheduler. Retained
records, grants and previous chats never restore opt-in.

Debugging remains separately opt-in and off by default. Retrospective setup or
participation does not start it. Identify any known current debug session and
pass its exact ID to begin, which stops it before freezing/exporting evidence;
debugging stays off during and after review. Without debugging, review uses the
visible conversation and explicitly selected evidence and discloses missing
observations; it cannot reconstruct private transcripts or infer voice/display
behavior. Already-authorized pending normal saves finish first, but an unsaved
draft is never saved just to enable a retrospective.

Each independent evidenced problem gets a separate finding and, if approved,
one issue. Reports default to a scrubbed, generalized summary with no raw-log
attachment. The writer reviews diagnostics and the complete actual outgoing
title, body and any selected attachments before exact-content approval. Excerpts
use a separate sharing copy; full-debug sharing requires separate approval of
the frozen ZIP and its complete member inventory, with privacy implications.
There is no automatic private archive upload. Credentials and hidden reasoning
must not be shared; if safe sharing cannot be established, the finding stays
local. Current-session approval/direction is required for publication and upload;
saved approval alone does not authorize a later chat.

Before creating an issue, the host compares bounded public issue/PR listings
semantically for duplicates, without private search terms or automatic comments.
Unknown issue creation is reconciled rather than blindly retried. Issue-body
creation and host-assisted attachment upload have separate states: Python does
not upload attachments, and a manual handoff is not a completed upload. This
workflow creates no code fix, branch, push, PR, story exchange or novel commit.
See the [workflow and exact JSON contracts](../../workflows/retrospective.md).

### Complete side-character profiles

`$novel-side-character` or an ordinary side/supporting/minor-character profile
request asks up to three missing basics, one at a time, then offers connected
provisional profile prose of roughly 400–700 words, shorter when requested or
appropriate. Discuss, revise, cancel or say **“Save this profile”** to accept and
save the current profile without a second approval. Selective saves remain
available. Existing Character and Character Development methods remain available.

Notebook intake, profiles and revisions stay entirely in chat until clear save
approval, with no guaranteed recovery of unsaved drafts. Legacy novels retain
normal sourced discussion/proposal capture and save-before-display rules;
capturing a proposal does not accept it as canon. Approved saves preserve owning
identities, provenance and history and do not authorize manuscript or unrelated
character changes. See [usage, format differences and updates](../side-characters.md).

## Install and explicitly update projects

Requires Python 3.11+ and Git 2.39+. **Only after publication**, install or upgrade
the exact package in the intended external/isolated environment:

```text
python -m pip install --upgrade novel-creator==0.10.2
```

Installing Python resources or updating/enabling a plugin leaves existing
novels' pinned snapshots unchanged. Do not reinitialize or convert a book to
obtain either feature. Current source and local candidate artifacts can be used
for disposable evaluation; that does not establish public availability.

| Project case | Side-character delivery | Issue retrospective delivery |
| --- | --- | --- |
| New legacy novel | Authorized initialization installs the legacy skill, workflow and root routing. | Initialization installs the legacy retro skill and shared workflow/routing. |
| Existing legacy novel | After publication, external-controller framework update preview/apply selecting 0.10.2. | The same reviewed framework update delivers the issue workflow and skill; old producer behavior is retired. |
| New format-1 notebook | Initialization installs rendered workflow/root routing and project skill, or uses the matching enabled plugin entry. | Initialization installs the rendered retro workflow/root routing and project skill, or selected plugin entry. |
| Existing format-1 notebook | Default standalone Codex/project notebooks can use focused `notebook update`; all supported host/source layouts can use the explicit feature-only helper. | Explicit `retro issue setup` preview/apply installs the entry/routing and refreshes only recognized shipped related guidance. |

Follow the complete [side-character update sequence](../side-characters.md#install-or-update-the-unpublished-candidate)
and [retrospective update sequence](../upgrading-projects.md#unreleased-session-issue-retrospectives).
Notebook paths cover English/Icelandic, Codex/Claude Code/both and project/plugin
layouts. Update/enable the matching plugin where selected; do not add duplicate
project skills. Legacy books remain standalone. The ordinary legacy updater
requires a published stable target; offline candidate tests use fixture transport
and do not bypass public discovery for real books.

Legacy framework application creates its dedicated framework-only commit.
Both side-character notebook update routes and `retro issue setup` leave resource changes
uncommitted and create no novel save or checkpoint. Issue setup installs the
retrospective workflow and applicable project skill/root routing, refreshes
recognized debugging/help/conversation snapshots, supplies missing linked writing
guides and adds the notebook local ignore rule. Story content, manuscripts,
history, custom instructions and unrelated staging remain protected. Customized
managed resources, conflicting routing, redirected paths and stale previews
refuse; inspect partial writes and take a fresh preview before resuming.

After applying either format's update, review the actual changed resources,
selected root instructions, skill files or enabled plugin entries and their
linked workflows. Have the host reread/reload them in the novel folder, possibly
in a new chat. Package imports and file checks do not prove native discovery.

## Compatibility and limits

No story-format conversion, new writing role or profile schema is introduced.
The side-character notebook helper refuses mixed/retained-legacy books. Issue
setup requires a valid independent format-1 notebook Git root and refuses
legacy-only books; mixed-marker notebooks retain their actual legacy debug
location without log conversion or relocation. See the upgrade guide for the
distinct maintenance boundaries.

The old `retro begin/review/compare/prepare/validate/publish` producer commands
are retired and refuse new contribution work, including `--authorize-draft-prs`.
Existing authentic matching grants support explicit `--recovery-only` enablement
and old-run reconciliation/release, not new grants or issue publication.
Historical records, receipts, notices, worktrees, branches and PRs are preserved;
uncertain remote creation remains blocked pending reconciliation. Existing
notice recovery continues through normal authorized saved replies, without an
unsolicited story turn. This is an intentional compatibility change for callers
of the old mutating CLI.

Earlier focused Windows side-character checks exercised synthetic
previous-public new/existing format delivery, stale/custom/redirected-path
refusals and partial resume. Local wheel/source isolated installs exercised
new setup and fixture-driven 0.10.1 updates, preserving story, history, custom
instructions and staging in those cases. These scoped results do not qualify
the complete two-feature release. Full Linux and required Windows release
checks, complete wheel/source verification, public installation and release
evidence remain pending. Native skill discovery/reload, voice behavior, plugin
enablement, attachment byte integrity and subjective writing quality remain
unverified by structural tests.
