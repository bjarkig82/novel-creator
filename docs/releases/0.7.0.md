## Changes from 0.6.0

New story notebooks receive three optional chat skills, also available through
ordinary-language requests:

- `$novel-clarify` asks focused questions about a character, outline, scene,
  chapter or other identifiable target. It asks one question at a time, defaulting
  to at most five per pass, and integrates clear answers into authoritative owning
  notes while preserving stable identities, writer decisions and history. Unknowns,
  intentional ambiguity, skipped questions and early stopping remain supported.
  Clarification does not rewrite manuscript prose.
- `$novel-analyze` compares selected material with relevant accepted notes,
  directions and outlines, returning prioritized findings with actual passages
  or locations, stable finding IDs, revision basis, consequences and suggested
  remedies. It distinguishes objective events, character beliefs and reader
  revelation. The pass is strictly read-only, including no automatic notes,
  review files, summary changes, staging or checkpoints. `$novel-review` retains
  its existing behavior of saving substantial requested findings.
- `$novel-help` offers a few suitable next steps or explains how an actually
  installed skill works. No input is required; optional input can be a command
  name, goal, topic or `commands` for the inventory. It explains purpose, expected
  and optional inputs, save effects and examples. Natural-language names and
  descriptions can identify targets; known IDs and file paths are optional.
  Help makes no file changes, executes no examples and switches no native role.
  An actionable request such as “Help me revise this scene” still follows the
  manuscript workflow.

The initialized notebook instructions route these methods explicitly and exempt
analysis/help from ordinary automatic note maintenance. Skills and linked shared
workflows are installed together. Existing writing roles, research, drafting,
outlining and review remain available. See the
[help examples](../writing-agents-usage.md#help-choosing-a-next-step-070) and
[clarification/analysis examples](../writing-agents-usage.md#clarify-and-analyze-070).

Packaging verification now uses the frozen 26-resource layout for the approved
public 0.5.0 wheel rather than requesting newer resources from that historical
artifact. Candidate/current checks remain strict about source resources; missing
required historical resources still fail verification.

## Installation and existing novels

Install or upgrade the exact published release in your configured environment:

```text
python -m pip install --upgrade novel-creator==0.7.0
```

[Novel Creator 0.7.0 is available on PyPI](https://pypi.org/project/novel-creator/0.7.0/).

After installing 0.7.0, initialize a **new** notebook at a new destination to
receive these skills. Open that notebook's folder and read its generated
instructions. See [setup](../../workflows/start-here.md#ask-your-agent-to-set-up-a-story).

Installing the package leaves existing notebooks and pinned legacy runtime,
workflows and skills unchanged. Existing notebooks are not retrofitted; no
notebook migration or updater is added. Do not initialize over an existing novel
to obtain the additions. Legacy novels retain their separate supported update
workflow, and these new notebook skills do not convert them. There is no new
Python subcommand, record-schema migration or per-turn runtime requirement.
