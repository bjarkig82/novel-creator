# Novel Creator 0.4.0 candidate

**Status: unpublished candidate.** PyPI still serves 0.3.0. Native Windows
Codex Desktop notebook behavior remains unverified; structural tests do not establish
conversational behavior or literary quality. This is a minor release adding an
optional workflow for new novels, compared with the published
[0.3.0 existing-book updater](0.3.0.md).

## New Markdown story notebooks

`novel-creator notebook init "My Novel"` creates an independent native Codex
Markdown story notebook with English or Icelandic seed content and optional
path and title. Python is used for setup; writing uses Codex's native file and
Git tools. Topic notes retain proposed and accepted ideas, decisions, open
questions, sources and revisions. A working summary helps navigation. Writers
can request a topic brief; the workflow does not request automatic recaps.
This workflow does not use the legacy exact-exchange ledger or its per-turn
Python save-before-display gate.

The explicitly invoked `$novel-outline` skill proposes and refines a book outline
from relevant notes and saves the chosen structure as a linked topic. It supports
English and Icelandic, preserves existing outline edits and history, and keeps
proposed facts and open questions distinct from accepted structure. It requires
no fixed act framework or invented ending, creates no chapter or scene manuscript
files, and adds no CLI command.

Stage-aware brainstorming starts broadly with the writer's interests when no
concept exists, asks one question at a time, and adapts its focus and method as
answers accumulate. Explicit topics or methods take priority, including mind
mapping before a subject is known. Optional `$novel-book-idea`, `$novel-premise`,
`$novel-character`, `$novel-plot` and `$novel-setting` skills offer focused entry
points without requiring a checklist or outline. Suggestions remain provisional
until accepted; moving on does not resolve open questions. Outline invocation
remains explicit-only. See [functionality](../functionality.md) and the
[brainstorming evaluation scenarios](../../tests/evaluations/brainstorming.md).

## Other changes since 0.3.0

Beginner setup and everyday-writing guides clarify installation and platform
limits. Legacy contributor networking retains host proxy and certificate settings
through its filtered transport environment. Windows release checks now handle
case-insensitive proxy variable names and retain notebook resource LF bytes;
these test and checkout corrections preserve strict artifact verification.

## Installation and compatibility

After 0.4.0 is published, install or upgrade in your external Python environment:

```text
python -m pip install --upgrade novel-creator==0.4.0
```

**This pinned PyPI command is usable only after publication.** Until then, use
only an explicitly identified candidate wheel or a source checkout for evaluation.
Python 3.11+, Git 2.39+ and an existing Git identity are required. For a notebook,
choose a new destination outside existing Git repositories; even an existing
empty directory is refused. Follow the [README notebook setup](../../README.md#new-story-notebook-040-candidate).

Installing the package leaves existing novels and their pinned resources
unchanged. Legacy commands and the existing-book updater remain available; use
the [update guide](../../workflows/getting-started.md#updating-an-existing-book)
for an explicit supported legacy update. The new notebook is for new novels only:
it does not migrate legacy books or automatically update existing notebooks.
Existing notebooks do not acquire outline or brainstorming additions automatically.

records immutable candidate identities and Windows/Linux qualification. Earlier

this source needs its own fresh candidate qualification before publication.

explicitly unverified native Windows and Linux notebook behavior. Qualification
requires successful full Windows/Linux suites, strict wheel verification, clean
wheel/source installations and the Linux literal Bash guide from the exact
immutable candidate. Windows automated CLI/install checks do not establish a
literal PowerShell guide journey. Native Desktop and that manual guide journey
are not claimed as passed. The protected PyPI environment review remains required.
Linux Codex Desktop remains explicitly unverified; macOS support is deferred.
No publication date, native notebook acceptance or writing-quality claim is made.
