# Novel Creator 0.8.0

**Published 2026-11-12.** [PyPI 0.8.0](https://pypi.org/project/novel-creator/0.8.0/)
contains the exact qualified wheel and source archive. Full Linux and Windows
qualification, both public installation checks and independent public installation
passed. The annotated `v0.8.0` tag is verified at the qualified source. The
[GitHub release](https://github.com/bjarkig82/novel-creator/releases/tag/v0.8.0)
has both qualified distributions and both reproducible plugin ZIPs, with verified
remote hashes. The previous published version is
[0.7.2](0.7.2.md), published 2026-11-11.

## Changes from 0.7.2

New Windows/Linux notebooks can use the `novel-creator` marketplace plugin in
Codex or Claude Code. Both catalogs use `novel-creator-marketplace`. The plugin
includes setup and fourteen writing methods, with shared workflows pinned into
each independent book. Setup installs six project-local writing roles per
selected host. Help and Analyze remain read-only; Clarify retains suggestions,
custom input and writer authority. Outlining remains explicit-only.

The standard-library bootstrap creates and verifies an isolated per-version
Python environment outside the book and plugin cache. It checks Python 3.11+,
Git 2.39+, exact package identity, healthy dependencies and local-wheel
provenance. Owned partial runtime failures can retry without deleting evidence.
Unknown directories, unsafe redirects and incompatible cache sources are
refused. Existing Git identity is required; setup changes no global identity.

Direct notebook initialization adds `--host codex|claude|both` and
`--skill-source project|plugin`. The original Codex/project default is preserved.
Plugin books carry `.novel-notebook/integration.json`, root host instructions
and native role definitions, with no duplicate project-local skills. Cached
entries resolve into the selected book's workflow snapshots.

## Availability and upgrades

| Project | 0.8.0 behavior |
| --- | --- |
| New legacy novel | Existing standalone setup and 0.7.2 methods remain available. No marketplace host port. |
| Existing legacy novel | Continue installed routing and the reviewed legacy updater. No implicit conversion. |
| New notebook | Default standalone Codex/project setup, or opt into plugin host integration during initialization. |
| Existing notebook | Keep installed routing/resources; original-layout notebooks retain their supported focused-method updater. Marketplace adoption is deferred. |

Python package installation alone does not rewrite any book. A plugin update
changes cached entries; project workflow snapshots remain pinned. Plugin removal
leaves novel data and history in place. The existing notebook updater refuses
nondefault integration layouts before writing; it does not adopt an existing
book or migrate plugin snapshots. Do not reinitialize a book to obtain a feature.
See [project upgrades](../upgrading-projects.md) for existing-format procedures
and Codex reload steps.

The plugin bootstrap installs the exact manifest version from PyPI. Normal
published-index bootstrap from the GitHub-installed Claude plugin created and
reused the isolated runtime and initialized English/Icelandic dual-host notebooks.
An explicit `--wheel PATH` remains available for local artifact validation.
Follow [marketplace setup](../plugin-marketplaces.md) for host commands, cache
locations, runtime provenance and project handoff. To install or upgrade the
package in your configured environment:

```text
python -m pip install --upgrade novel-creator==0.8.0
```

After installation, reload the plugin in the actual host and open the intended
book itself. Existing standalone projects still need their separate reviewed
project update and instruction/skill reload; installing the package is only the
first step. There is no migration requirement for continuing an unchanged book.

passed the full Linux suite (509 tests, three skips) and the full Windows suite
(509 tests, no skips), plus early project-upgrade guards on both platforms.

notebooks, compatibility updates from the hash-verified public 0.7.2 wheel,
wheel bytes/legacy journeys and clean wheel/source installations. Linux also
passed the literal Bash guide journey. These results are bound to source
`9491664acccec5c9cb1f9c2ce6315883328aaeeb` and the exact published distributions.

The [publication run](https://github.com/bjarkig82/novel-creator/actions/runs/43230160921)
passed public named-package installation and archive verification on Linux and
Windows. Linux passed on a retry after initial PyPI index propagation; only the
failed public check reran, without another publication. Separate public
installation passed with no dependency inheritance. The annotated tag object
`8484e06ea3c9bc55e80fe21ec226b826097bb064` peels to the qualified source above;
later documentation/evidence changes do not change that release source.

An isolated Claude Code 2.1.322 GitHub marketplace installation reported fifteen
skills and zero plugin agents; setup writes six project-local roles per host.
Codex CLI 0.163.0 earlier reported catalog availability, without native installation.
See the [canonical release evidence](../../tests/evaluations/release-0.8.0.md)
and [candidate record](../../tests/evaluations/release-0.8.0-candidate.json)
for immutable hashes, platform reports and public verification. Earlier local
builds and lifecycle probes remain in the historical
[marketplace ledger](../../tests/evaluations/marketplace-0.8.0.md).

Automated Windows/Linux qualification does not establish native desktop skill
discovery, authenticated conversations, specialist controls, literary quality or
voice behavior; those remain unverified. macOS, existing-notebook marketplace
adoption, a legacy host port, MCP and public-directory submission are deferred.
