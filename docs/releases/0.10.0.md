# Novel Creator 0.10.0

Status: **published 2026-11-13** on PyPI, compared with [0.9.0](0.9.0.md).
Full Linux and Windows candidate qualification passed. Both published artifact
SHA-256 hashes match the qualified candidate, and the annotated `v0.10.0` tag
points to its source commit. Windows public installation passed. The Linux public
installation check passed on retry after the first attempt encountered PyPI index
propagation delay; the upload was not repeated.

Install or upgrade:

```text
python -m pip install --upgrade novel-creator==0.10.0
```

This release adds opt-in session debugging to legacy novels and Markdown
notebooks. Ask to start the session with debugging, then ask to stop debugging
and export a report. A local ZIP contains a readable timeline, structured
events and captured working content. Package-measured operations and
agent-recorded observations are distinguished; unavailable host information
and capture gaps remain unknown. Content can include public messages and story
text, and reports are retained locally. Capture is off until explicitly enabled
for the current session; interrupted logs remain available for later export.

| Format and age | Availability and follow-up |
| --- | --- |
| New legacy novels | Pinned framework includes debugging and its workflow. |
| Existing legacy novels | Explicit reviewed framework update is required after package installation. |
| New notebooks | Debugging guidance is included at setup for the selected host and skill source. |
| Existing notebooks | Run the explicit debug setup described below for the selected notebook. |

Installing the package does not rewrite an existing novel. For a legacy novel,
use its configured external controller to preview the published release:

```text
CONTROLLER -I -B -m novel_creator update --novel BOOK --python RUNTIME --version 0.10.0 --json
```

Review changed paths, blockers and HEAD, then apply that exact preview with its
returned identifiers:

```text
CONTROLLER -I -B -m novel_creator update --novel BOOK --apply --preview PREVIEW_ID --version 0.10.0 --expected-head REVIEWED_HEAD --json
```

Follow the [legacy update procedure](../../workflows/getting-started.md#updating-an-existing-book)
for client closure, quiescence and recovery. The reviewed framework update
preserves story records, manuscripts, custom instructions and unrelated staging.

For an existing format-1 notebook, use the installed package's focused setup:

```text
novel-creator debug setup --novel PATH --json
```

This installs the debugging workflow, adds a pointer to each selected host's
root instructions and adds the local ignore rule. It supports Codex, Claude Code
and both-host notebooks with project or plugin skills. It preserves custom
guidance, story files, Git history and unrelated staging; conflicting debug
resources stop setup instead of being overwritten. Setup does not commit.
Plugin users should also update and enable the matching plugin. After either
format's update, reread the selected root instructions and linked workflow, and
use the host's available reload or reopen controls. Installing Python or the
plugin alone does not refresh project-local snapshots.

The [notebook workflow](../../notebook/workflows/debugging.md) and
[legacy workflow](../../workflows/debugging.md) describe controls, report
contents, interruption handling and the external-controller fallback during a
legacy update hold. Debugging adds overhead and is not a complete host trace.
Actual Codex/Claude Code conversation capture and native discovery remain
unverified; automated structure and Windows/Linux CLI checks do not establish them.
