## Changes from 0.5.0

Legacy conversation gets fresh working context and targeted retrieval instead of
loading the complete exchange archive on ordinary turns. `context --view working`
derives navigation from the currently validated committed journal every read,
bound to its novel identity and checkpoint. It retains complete project settings,
preferences/directions, selected complete current records, all active findings,
holds, availability/coverage and the last saved reply. No provider service,
database or trusted stale summary cache is added.

Repeatable `--focus ID` and Unicode-normalized case-insensitive lexical `--query`
retrieve complete records and bounded incoming/outgoing links. Focus and query
combine with explicit IDs first; matching all query terms is lexical navigation,
not semantic search or exhaustive continuity review. Session navigation does not
recursively pull in the entire book. A selected session controls summary/fallback
and saved-response scope without filtering explicit/query results elsewhere.

`--limit` defaults to 12 selected records, range 1–100. The complete global project
and active findings are additional, so this is not a token budget. Missing focused
IDs fail with error 4; too many explicit IDs for the limit fail with error 2 rather
than being silently dropped. Omissions, outstanding linked IDs and historical
revision references are reported so agents can retrieve missing context. Agents
inspect exact historical wording and source artifacts when needed. See the
[working-context workflow](../../workflows/working-context.md) for commands.

`context --view current` keeps current records/settings while omitting the archived
exchanges. The default `context`/Python API remains the prior full shape, also
available explicitly with `--view full`. Retrieval flags require the working view.
All views validate the committed source and fail closed on damaged history.

Shipped legacy entry, brainstorming, initialization and resume guidance now use a
fresh working view before each response, retrieving complete relevant records and
sources on demand. Loaded workflows and a verified runtime may be reused while
valid. The journal remains the sole authority: original status, sources, stable
IDs, revisions and historical exchanges are unchanged. Exact current-input capture,
unchanged input artifacts and save-before-display, including creative progress
commentary, remain required. A saved response never proves display or acceptance.

New native Markdown notebooks keep the existing derived working-summary navigation
and owning topic files. Guidance emphasizes reading complete relevant items,
reconciling stale summaries after saves/writer edits and sharing the same saved
authority across roles. The earlier source responsiveness guidance is included:
when context suffices, respond usefully, reuse valid guidance/focused context and
reduce unnecessary tool round trips while completing required saves/checkpoints.
Notebook writing still uses native host file/Git tools and no legacy per-turn
Python or exact-transcript protocol.

## Installation and existing books

Install/upgrade the exact published release in your configured environment:

```text
python -m pip install --upgrade novel-creator==0.6.0
```

[Novel Creator 0.6.0 is available on PyPI](https://pypi.org/project/novel-creator/0.6.0/).

Installing a package does not replace an existing book's pinned runtime, workflows,
skills or notebook instructions. New legacy novels receive the new bundle at
initialization; existing legacy novels require an
[explicit supported update](../../workflows/getting-started.md#updating-an-existing-book)
with clients closed as required and instructions reloaded after
verified ready completion. Keep older pinned commands until that update succeeds;
new source instructions must not be copied over an older runtime. Story identity,
records, original status/provenance and writer authority are preserved. There is
no record-schema migration.

Native notebook guidance ships into newly initialized notebooks. Existing Markdown
notebooks are unchanged; no conversion, notebook migration or updater is introduced.
Reading this source guide or upgrading the package does not retrofit their files.
