## Six writing roles for new notebooks

New notebooks install six project-scoped `.codex/agents/` definitions:
`novel_orchestrator`, `novel_brainstormer`, `novel_researcher`,
`novel_scene_writer`, `novel_chapter_writer` and `novel_reviewer`.
The root conversation follows the orchestrator by default. It handles small
requests directly and coordinates bounded research, substantial drafting and
independent assessment when useful. A writer can request a specialist in ordinary
language; with native client support, that specialist remains their conversation
partner until they choose another role.

Optional `$novel-agent`, `$novel-research`, `$novel-scene`, `$novel-chapter` and
`$novel-review` skills provide focused entry points. Existing brainstorming and
explicit-only outlining remain available. Ordinary writing needs no repeated
skill invocation, per-turn Python command or exhaustive questionnaire. Roles
inherit host tools, permissions and model settings; they add no provider API,
model credential, browsing service or separate runtime requirement.

## Manuscripts, research and independent review

Shared workflows cover scene and chapter drafting, scoped revisions, bounded
research and requested reviews. Manuscripts, research and reviews are created on
demand; setup creates no empty forms.

- `manuscript/index.md` records stable chapter/scene identities, order and owning
  files. Each scene has one editable prose owner. Incorporating a standalone
  scene transfers it into its chapter and retires the old editable copy.
- Revisions preserve exact current prose in verified Git history or a verified
  historical copy before replacement, including uncommitted writer edits. Requested
  scope and protected passages remain binding; interrupted transfers and
  concurrent edits require inspection and reconciliation.
- `research/<research-id>.md` records actual consulted sources, supported claims,
  uncertainty and story implications. Missing browsing or source access must be
  disclosed; research does not establish fictional canon.
- `reviews/<review-id>.md` records passage-based findings tied to the reviewed
  revision. Independent review requires a separate native context. Findings alone
  do not authorize rewriting prose or changing accepted facts.

The project brief and notebook topics retain authority. Drafting permits creative
invention without accepting every new story fact; only clear writer acceptance
establishes selected facts. Saved agent memory is not a second canon. During
delegation, specialists edit only assigned paths and do not commit; the coordinator
owns shared notes, integration and the local checkpoint. Direct specialists may
save requested work under the same scoped rules. See the
[writing-agent usage guide](../writing-agents-usage.md).

## Installation and compatibility

**Usable only after 0.5.0 is published:**

```text
python -m pip install --upgrade novel-creator==0.5.0
```

Until publication, [0.4.1](https://pypi.org/project/novel-creator/0.4.1/) remains
the verified published package. Python 3.11+, Git 2.39+ and an existing Git
identity remain required for setup. Open the initialized novel folder itself in
Codex and read its instructions and saved context before continuing. A parent
workspace does not guarantee discovery of nested project instructions.

These additions install into **new notebooks only**. Package installation leaves
existing notebooks, legacy novels and pinned resources unchanged. There is no
existing-notebook migration or new updater command. Notebook format 1, stable
identities, retained history and writer authority remain unchanged; no record
migration or breaking format change is introduced. Legacy novels retain their
separate runtime and [explicit update workflow](../../workflows/getting-started.md#updating-an-existing-book).
Notebook writing retains its native file/Git model, without legacy transcript
archival or a save-before-display gate. Agent-led setup handoff and explicit legacy
realtime capture already shipped in 0.4.1 and are not new in 0.5.0.
