# Novel Creator 0.10.1

Status: **unpublished candidate**, compared with the verified published
[0.10.0 release](0.10.0.md). Full candidate Linux/Windows qualification,
publication, public artifact verification and the annotated source tag remain
pending. There is no publication date yet.

## Changes since 0.10.0

The local debugging ZIP's readable report now counts exact operations and
operation/source pairs, keeping user messages, assistant messages, prepared
responses and explicit `capture.gap` events distinct. It reports availability
of nonempty observation timestamps and correlation-ID objects without copying
their values or message content into that coverage summary. Counts describe
readable recorded evidence: zero does not prove an action was absent, ingestion
time does not establish observation time, and stopped/partial describes the
recording lifecycle rather than completeness. The report builder is shared by
legacy novels and notebooks.

Notebook guidance more precisely distinguishes discussion, selected approval,
verified file saves and verified Git checkpoints, including during voice
continuations and role handoffs.
Approved but unwritten work remains unsaved; saved files can have a pending
checkpoint. Character-development drafts stay in chat until explicitly authorized
and actually written to the owning file; an approved pending save is still
unwritten. A narrowly scoped authorized Git permission retry may use the host's
approved access route after inspection;
otherwise the checkpoint limitation is disclosed, preserving unrelated staging.
These are workflow instructions, not a voice speed or reliability guarantee.

A writer can request a local read-only notebook retrospective using a selected
debug archive or other selected public evidence. Findings distinguish observations,
hypotheses and missing evidence, citing archive members/event sequences without
copying private writing into framework contributions. This workflow does not use
the legacy contributor retrospective CLI, activate capture, save story notes or
authorize external communication. It cannot reconstruct missing messages or infer
display, voice behavior or latency causes from gaps.

Existing notebooks now have an exact documented preview/apply procedure for the
revised shared session guidance. It checks public 0.10.0 resource provenance,
preserves existing skills/roles/custom root text and adds bounded root routing.
Installing Python or a plugin alone still leaves project snapshots unchanged.

## Availability and compatibility

| Format and age | Delivery and follow-up |
| --- | --- |
| New legacy novels | Initialization pins the revised shared report builder and legacy debugging workflow. Legacy structured saving remains intact. |
| Existing legacy novels | Install the selected package, then preview/apply its explicit framework update to replace pinned runtime/resources. |
| New notebooks | Setup supplies revised conversation, character-development, role and debugging guidance for English/Icelandic and Codex/Claude Code/both with project/plugin skills. Debugging uses the installed package when explicitly enabled. |
| Existing notebooks | Install the selected package, update/enable the matching plugin if used, then run the reviewed manual session-guidance preview/apply below. Existing debugging setup remains an explicit prerequisite if absent. |

There is no format conversion, schema migration or legacy notebook-style
character-profile method. Legacy structured save rules remain separate. The
manual notebook procedure requires an independent format-1 Git notebook with
the supported shared workflows; a manually migrated book retaining
`.novel-creator/` is refused and needs a separately reviewed adapter/maintenance
path. Do not delete markers or legacy state to bypass guards.

Customized shared workflows, customized bounded routing, redirected paths,
hardlinked destinations and stale previews fail safely. Current identical
resources are retained. Older or customized snapshots need intentional review;
the focused `notebook update` command remains a separate bounded older-method
installer and does not refresh all session guidance.

## Installation and project update

Use Python 3.11+ and the configured isolated environment outside the novel.
The following version-pinned command is usable **only after publication**:

```text
python -m pip install --upgrade novel-creator==0.10.1
```

Before publication use reviewed candidate artifacts in an isolated environment;
do not treat this command as evidence of PyPI availability. Plugin books also
need the matching reviewed plugin enabled in the actual host. New notebooks and
legacy novels receive their respective resources through normal initialization;
never initialize over an existing book.

For an existing legacy novel, use the configured external controller and runtime:

```text
CONTROLLER -I -B -m novel_creator update --novel BOOK --python RUNTIME --version 0.10.1 --json
CONTROLLER -I -B -m novel_creator update --novel BOOK --apply --preview PREVIEW_ID --version 0.10.1 --expected-head REVIEWED_HEAD --json
```

The release-selecting commands are usable after publication. Review the first
command's target, changed paths, blockers and HEAD before using its identifiers
in the second. Follow [legacy client closure, quiescence and recovery](../../workflows/getting-started.md#updating-an-existing-book).
The framework update makes its dedicated local commit and preserves story
records, manuscripts, custom instructions and unrelated staging.

For an existing notebook, first ensure optional debugging is installed when it
was absent, using `novel-creator debug setup --novel PATH --json`. It does not
refresh differing existing debugging guidance. Then save the **exact** snippet
from [Update session guidance](../session-guidance-upgrade.md) outside the notebook.
Pause editing and run it with the notebook itself as the working directory:

```text
python /absolute/path/session-guidance-upgrade.py preview
python /absolute/path/session-guidance-upgrade.py apply PREVIEW_ID REVIEWED_HEAD
```

Review the returned package/resource location, changed paths, preview ID and HEAD
before application. The procedure binds inspected bytes, identities, host/language,
package outputs, Git index and HEAD; changed inputs require a fresh preview.
Only four shared workflows and selected root routing may change. It leaves story
files, custom root bytes, skills, roles, history and unrelated staging intact,
without committing or pushing. This is manual maintenance with editing paused,
not a cross-file transaction: inspect partial writes after interruption and take
a fresh preview after reconciliation.

After either format's verified update, have the host reread selected
`AGENTS.md`/`CLAUDE.md` and linked workflows. Inspect actual project skills and
their links, or actual enabled plugin entries, then use the host's supported
reload/reopen controls, possibly a new chat. There is no universal reload command;
unsaved chat drafts have no guaranteed recovery. See the complete
[format-specific upgrade guide](../upgrading-projects.md).

## Validation and limits

Local focused delivery checks exercised the exact notebook procedure across all
twelve host/source/language layouts from the public 0.10.0 wheel under installed
candidate wheel and source-distribution runtimes. They checked resource/skill
links, new legacy setup, previous-release legacy updates, current retries,
stale/custom/unsafe-path refusals and preservation of story, custom instructions,
skills, roles, Git HEAD/history and unrelated staging. Those local artifact checks
do not replace immutable-source full release qualification.

Native Codex/Claude Code discovery, instruction reload, actual display/voice
delivery, specialist interaction, archive completeness, responsiveness timing and
subjective writing quality remain unverified. Structural tests and successful
Python imports do not establish those behaviors. Debug capture remains explicit,
local and session-specific; archive review neither uploads nor publishes content.
