## Changes since 0.10.2

Suggestions adapt after repeated requests rather than repeating the same choices.
Notebook guidance favors readable, independently addressable current notes,
derived navigation and proportionate orchestration. It preserves writer authority,
existing save rules and the distinction between provisional ideas and accepted canon.

Debug record help explains supported operations, story paths and snapshot phases.
Both formats include a UTF-8 JSON recipe usable from PowerShell without inserting
story text into commands. Capture failures stay explicit gaps; later snapshots
cannot reconstruct a missing before state. Exported reports label their environment
as the session-start snapshot, including for older sessions. That snapshot is
preserved across upgrades and does not establish per-operation runtime provenance.

The first retrospective response gives concrete publication next steps. Exact
current approval is still required for sharing, issue publication and attachments;
there is no automatic upload, fix or PR. Debugging and optional retrospective
participation retain separate active-session opt-ins.

## Install and explicitly update projects

Requires Python 3.11+ and Git 2.39+. Use an isolated environment outside novels.
Install or upgrade the exact published package:

```text
python -m pip install --upgrade novel-creator==0.10.3
```

Installing Python or updating/enabling a plugin leaves existing books' pinned
resources unchanged. Follow the [complete format-specific instructions](../upgrading-projects.md).

| Project case | Required delivery |
| --- | --- |
| New legacy novel | Authorized normal initialization from 0.10.3 installs the legacy workflows, skills and routing. |
| Existing legacy novel, including 0.10.2 | External-controller framework update preview/apply selecting `--version 0.10.3`, reviewing exact preview and HEAD. No same-version bypass. |
| New format-1 notebook | Normal initialization from 0.10.3 installs shared workflows and selected project skills or matching enabled plugin routing. |
| Existing notebook, including 0.10.2 | Install externally; update/enable matching plugin where selected; add side-character prerequisites only if missing; run `retro issue setup` preview/apply first, then the exact [six-guide preview/apply procedure](../session-guidance-upgrade.md). |

Issue setup refreshes retrospective/debugging/conversation/Help and actual
entry/routing; the six-guide step refreshes brainstorming, format, role and
character guidance. Both steps are necessary for 0.10.2 notebooks. Do not add
duplicate project skills to plugin books. Notebook maintenance leaves resource
changes uncommitted and creates no story save or checkpoint. Legacy framework
application creates its dedicated framework-only commit. Story content, history,
custom instructions and unrelated staging remain protected. Customized managed
resources, stale previews and unsafe paths refuse; inspect partial writes and
review a fresh preview before resuming.

Inspect actual skill files or enabled plugin entries, selected root instructions
and linked workflows, then have Codex reread/reload them in the novel folder,
possibly in a new chat. Package imports do not prove native discovery.

## Compatibility and remaining limits

and legacy persistence rules remain distinct. The legacy updater still requires
a newer published stable release; candidate fixtures do not authorize bypassing
public discovery on real books. Setup/update does not activate debugging or
retrospectives, publish issues or rewrite a real novel.
