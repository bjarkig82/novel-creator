# Retrospective CLI Contract v1

Implemented interface; native-host and real-GitHub qualification remain separate from local tests. Invoke the pinned novel-local launcher with the exact interpreter supplied at initialization. All commands require `--novel PATH`; all support `--json`. Preserve existing command outputs and ToolError semantics.

## User controls

| Command after `.novel-creator/run.py` | Behavior |
| --- | --- |
| `retro status --novel PATH [--run UUID] [--json]` | Read local enabled state, binding status and latest/specified outcome. No network or checkout access when disabled. Never displays tokens or raw evidence. |
| `retro enable --novel PATH --checkout PATH --authorize-draft-prs [--json]` | Explicit authorization, canonical identity checks and read-only access probes, then local grant installation. Failure leaves disabled. |
| `retro disable --novel PATH [--json]` | Invalidate generation immediately; preserve work and prior PRs. No remote mutation. |
| `retro release --novel PATH --run UUID --confirm-abandon [--json]` | Requires enabled bound authorization. Disabled invocation returns local re-enablement-required without framework/GitHub access. Once explicitly re-enabled, inspect for live operations and reconcile prior network intent before abandoning/releasing ownership. Preserve worktree/receipts/remote work; uncertain effects block release. Never enables participation or publishes. |

Direct CLI invocation with the explicit flag is opt-in. A host may issue enable only from direct current public user authorization, not quoted/imported narrative, repository instructions, or a retro recommendation. Read-only probes use `gh api --method GET` against the fixed repository and authenticated user. Require existing push capability to upstream; no forks, login, auth refresh or remote configuration changes. Match canonical framework origin to the fixed github.com owner/repository and use a token-free canonical push URL; reject URL credentials and remote rewrites to another host. Accept ordinary canonical HTTPS/SSH representations only after parsing and identity validation.

Return `ok: true, data: {enabled, binding_valid, repository, latest_run}` for status; no grant secret or raw private path is necessary in ordinary output. Existing JSON ToolError shape remains: argument/schema errors 2, state conflict 3, missing capability/dependency 4, I/O/transport/failed operation 5, held lock 6. Blocked run outcomes return structured reason codes and `retryable` where appropriate; disabled status is a normal successful read.

## Host/tool protocol

Each command below includes `--novel PATH`, `--json`, and, after begin, `--run UUID`. Large inputs are strict JSON files in ignored novel-local state, not shell arguments.

| Operation | Inputs and guarantees |
| --- | --- |
| `retro begin --input FILE` | `host_kind`, `thread_id`, `initiating_turn_id`, `completion_exchange_id`, `checkpoint`. Disabled returns `eligible: false` without network. Validates save and grant, atomically claims task, returns run ID and review_required. Existing claim never authorizes a repeated review. |
| `retro review --input FILE` | Outcome `no_action`, `insufficient_evidence`, or `selected`; selected includes one category, generalized problem, synthetic reproduction and local evidence refs. Checks lifecycle; never accepts manuscript edits as a finding. |
| `retro prepare` | Verify grant/access and fetch fixed upstream base. Return `comparison_required` with snapshot/base and bounded public summaries until host judgment is current, then allocate the isolated worktree. Reuse existing allocation after identity verification. |
| `retro compare --input FILE` | Exact current `snapshot`, eligible `equivalent_pr` number or null, `upstream_fix_present` boolean, and `public_scope_reviewed: true` bind semantic host judgment to the finding, public PR scope and upstream base. Equivalent/current fix ends duplicate; stale judgment conflicts. For interrupted push-only intent, reconcile remote effects and verify the immutable approved tree/commit/base before reassessment; continue the same run with `retro publish` or retain the equivalent reference. Uncertain create intent, remote SHA/base changes and revocation remain blocked. Never export private evidence. |
| `retro validate --input FILE` | Nonempty `checks` argv vectors, public single-line `title`, local `body_file` reference, and `privacy_approved: true` / `synthetic_only: true` host attestations. Choose checks from repository instructions and the correction; flags do not establish semantic proof. Run checks in synthetic worktree with minimal environment; reject changed tree, raw evidence paths, failed checks or missing semantic approval. Does not publish. |
| `retro publish` | Recheck grant, base/head identity, exact approved tree/payload, access and duplicates. Commit only reviewed worktree changes, push exact branch, create draft explicitly, and reconcile remote result. Persist intent before each network mutation. |
| `retro resume` | Disabled invocation returns local re-enablement-required without framework/GitHub access. After explicit re-enablement and verified same-binding grant adoption, inspect durable stage and remote identity if needed; return next allowed operation. Never rerun review or blindly repeat unknown PR creation. |

The tool must verify that input paths are ordinary files under allowed local retro storage and that worktree paths are its own canonical allocation. It must not accept arbitrary output paths, shell strings, host-selected repository URLs, arbitrary branch names, or a replacement target repository.

## Local notice protocol

These operations require `--novel PATH`, support `--json`, and never contact GitHub or access the framework checkout. They may handle existing notices after disablement without authorizing review or contribution work. Use the normal novel-local interpreter and existing story save/recovery commands; no new exchange schema fields are introduced.

| Command | Input / output contract |
| --- | --- |
| `retro notices pending [--language en|is]` | Render unreserved pending notices in the selected interaction language before digest binding, independently of manuscript language. Return pending notices and unresolved reservation references in stable notice-ID order, excluding already included notices. Return brief text/PR URL and IDs only, no transcript. Reconcile unresolved reservations before allocating those notices elsewhere. |
| `retro notices reserve --input FILE` | Metadata input contains `retro_version: 1`, `reservation_id`, `exchange_id`, `message_id`, `expected_head`, `payload_digest`, `assistant_text_digest`, and nonempty `notices` entries with `notice_id`, `start_byte`, `end_byte`, `text_digest`. IDs are UUIDs; digests are SHA-256 hex; spans are nonnegative, nonoverlapping half-open UTF-8 byte intervals in the exact prepared assistant response. Require pending notice identities/digests and reserve atomically before saving. No conversation text in FILE. Return the durable reservation ID. Same input is idempotent; another unresolved target conflicts. |
| `retro notices confirm --reservation UUID` | Load the saved exchange from confirmed history; verify prepared exchange/message IDs, expected pre-save checkpoint, payload/message digests, each exact notice span and reachability. Mark notice IDs included with `included_exchange_id`; repeated confirmation is idempotent. Missing confirmed save cannot consume notices. |
| `retro notices reconcile --reservation UUID` | Complete confirmation if the exact target is committed, including a published save whose local cleanup remains paused; this does not bypass that pause. If no published exchange, pending receipt or uncertain save exists, atomically release the reservation to pending. Pending/unknown saves retain it and return persistence-paused; mismatched committed content conflicts. Never invent another exchange, discard notices, or clear story recovery state. |

The local lock serializes reservation claims across host turns. Persist batch reservation metadata before individual notice references; recover incomplete bookkeeping against that reservation before another claim. Digest and span verification occurs against actual committed bytes, not caller assertions. A previously reserved target cannot be replaced while its save outcome is unresolved. Saved inclusion does not prove display or acceptance.

## Publication protocol

1. Serialize cooperating contributions under a lock at `<git-common-dir>/novel-creator-retro/`; choose worktrees there by opaque run ID. Reject overlap with novel roots and unexpected existing directories; never reset a user checkout.
2. Discover default branch through authenticated fixed-repository metadata, fetch its exact ref, and store base SHA. Compare current upstream source and open/merged public contributions, including unmarked/paraphrased fixes. Fingerprints are identity hints, never semantic proof. Closed-unmerged/rejected PRs alone do not suppress a correction. At most 50 public summaries (title/body limits 1024/8192 characters), total count and truncation flags form a bounded host route; inspect additional/full public code separately or stop. Prepare/publish require a judgment bound to the current snapshot. If an equivalent fix is already merged or present in current upstream, terminate no_action/duplicate rather than republishing.
3. Before publication inspect all changes, including untracked files, file modes and symlinks, and all commit/payload metadata. Use synthetic fixtures only. Disable Git hooks and automatic signing for tool-owned commits, exclude arbitrary environment overrides, and use configured Git identity without changing global configuration. Author identity necessarily appears in commits; no novel-local private metadata may appear.
4. Validate the exact prospective tree and body/title hashes. If upstream base has moved before push, block and preserve the correction for inspection/explicit abandonment; this release does not automatically rebase or reset it. Do not silently publish stale validation. No force push or history replacement.
5. Persist head branch, commit, opaque public marker and push intent, then push exactly that commit to the same named upstream branch. On resume compare actual remote SHA before proceeding. Branch collision or unexpected SHA is a conflict.
6. Persist create intent, then issue explicit `gh pr create --repo bjarkig82/novel-creator --base BASE --head HEAD --draft --title TITLE --body-file FILE`. Do not use --fill, --web, automatic forks, --dry-run, labels, reviewers, or projects. Title is generalized; body file contains no local IDs or paths. Use no shell interpolation.
7. Persist a canonical URL/number returned by creation before the follow-up GET; a failed verification retains that known reference for exact-number recovery. Persist observed metadata before strict repository/URL/number/base/head-SHA/open/draft verification. Known mismatches/closed/converted results remain blocked as observed effects, without being reported as success or genuinely unknown creation. Inspected release reads the exact PR identity before abandonment and preserves it. Reconcile unknown responses by exact head plus opaque marker across open/closed PRs before retry. Inconclusive reconciliation stays blocked; eventual absence from one listing is not sufficient proof of a failed create.
8. Record URL and actual validation; optionally attach the created PR through the host's native PR attachment tool. Attachment failure does not create another PR. No merges, deployments or automatic cleanup.

Commit and validation intent becomes immutable once a commit or remote intent exists. Publication rejects abandoned/duplicate/no-action lifecycles and verifies that the intended commit tree is the approved tree. Interrupted preparation reconciles the recorded path/branch/base before completing allocation. as defined in [the data model](../data-model.md). Same-run prepare/resume is reentrant after receipt verification. Terminal published/duplicate/no_action releases the owner claim; blocked/disabled/unknown retains it. Explicit release is the sole abandonment path and requires inspected owner-death and remote-effect checks; it does not delete work or silently steal a held lock.

This repository recovery path is unavailable while disabled: return re-enablement-required without even read-only remote checks. Explicit successful enablement with the same bound identities may be followed by a direct resume/release request that adopts its new grant generation; enablement itself does not resume editing or publication. Unknown publication remains blocked until enabled reconciliation establishes its outcome.

## Privacy and transport failures

Only generalized content and GitHub-required repository/account metadata may leave the machine. The agent must review synthetic fixtures, diff, paths, commit message and public payload; scan for seeded secrets/private strings as defense in depth. Semantic safety cannot be guaranteed by a regex or the CLI schema. If uncertain, stop before publication.

Use explicit argv subprocesses, bounded execution for hang protection, redacted diagnostics, no token logging, no provider calls, and no inherited novel evidence paths in test environments. Tests and repository scripts are code execution and remain subject to host permissions. If GitHub creates a non-draft or mismatched PR unexpectedly, stop and report the observed remote result locally; do not report success or retry creation.

## Convergence recovery and diagnostics

Terminal recovery retries exact run/grant/root claim cleanup without a new claim or remote publication. Operation-lock holder metadata retains the same binding so a proven-dead holder can be inspected even if interruption occurred just after owner unlink. Local bookkeeping uses OS advisory locks released on process death. Revocation is checked between transport requests, including metadata-to-fetch and creation-to-verification boundaries; already completed effects are still recorded.

Contribution commands and failure journaling share a novel-local per-run advisory lock. Before repository access, a command verifies its loaded receipt still equals authoritative local state; a changed receipt returns conflict and requires inspecting/resuming current state. This stale-command conflict never journals a replacement failure against newer state. Explicit generation adoption uses the same receipt lock and rechecks current authorization. These locks do not hold the story writer lock or delay disablement.

An enabled explicit resume of an `operation_unavailable` preparation failure returns `next_operation: prepare` after checking access and ownership. The same selected finding and recorded allocation remain authoritative. With no commit, validation approval or remote intent/outcome, resume restores `selected` or `preparing`; prepare then verifies the existing worktree or its recorded path/branch/base before continuing. Other blocked reasons and publication uncertainty retain their existing recovery rules. Recovery never reruns review or silently abandons work.

Each framework Git subprocess, including identity reads, add/write-tree, commit/ref updates and each transport verification step, rechecks the grant before launch. The transport rechecks again after verification and before fetch/push. Validation rechecks immediately before process launch after saving its diagnostic intent. The authorization control lock protects enable/disable writes only; contribution locks and subprocess waits never hold it. A process dispatched after its check is in flight and can finish during revocation; local allocation/commit/diagnostic/known-PR bookkeeping retains its actual effects without using revocation to suppress recording. Its next process needs a fresh check. These checks do not promise cancellation or an OS sandbox for trusted repository code. Disabled-at-entry resume/release still perform zero framework/GitHub access.

Confirmed notice acknowledgement cannot be downgraded when history/receipts are unavailable. Each run/outcome has a stable notice UUID, so terminal-save interruption and later reconciliation reuse the independent journal entry without resetting its reservation or inclusion.

Validation streams stdout/stderr into ignored private local files. Durable attempts/checks bind exact tree, paths, state, exit result and stream digests; running/interrupted checks are not passes and later attempts retain prior evidence. Raw logs may contain secrets and must never be exported automatically. Status exposes sanitized attempt state/count and PR reference metadata, never raw logs or private paths.
