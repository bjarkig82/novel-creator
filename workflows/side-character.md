# Side-character profiles

Use this optional mode for `$novel-side-character` or an ordinary request to
create a complete side, supporting or minor character profile. Select it before
generic character enrichment, including requests that also say “fill the gaps”.
A character topic alone retains [brainstorming](brainstorm.md). This is a bounded
writing method, not a new role, schema, provider or separate profile store.

Follow [entry](entry.md), [working context](working-context.md),
[continuity](continuity.md) and [authority](authority.md), including exact current
input capture and save-before-display on every creative turn. This legacy mode
has no notebook chat-only exception. Unavailable exact current input or failed
save stops display of creative content under the normal entry safeguards.

## Read and ask only the missing basics

Read fresh working context, the project directions and configured language,
relevant complete character records, owning assertions/relationships, accepted
facts, exact sources and unresolved findings. Missing, unreadable or omitted
context is unavailable, never evidence of absence. Disclose material limits; do
not invent prior discussions. Names are display text, not identity. Preserve
stable IDs, accepted facts and explicit directions.

Ask up to three substantive missing basics, ONE AT A TIME: role, connection to
the cast, and fixed traits or constraints. Skip known answers; honor “shorter”,
“skip” or “you decide” immediately. Ask an extra identity or conflict clarification
only when necessary to avoid guessing between people or contradicting protected
facts, never to extend an interview. Clear writer answers retain their normal
authority under the sourced current-user decision rules; the generated profile
does not suspend that authority. Open questions retain their normal records.

## Propose one practical complete profile

Write one connected full 400–700-word profile, shorter when requested or when
context warrants, without padding. Cover identity, appearance, voice, personality,
motivation, relevant history, relationships and continuity cues in actual proposed
prose, not a checklist of things to write. Keep the scale useful for a side
character; do not force an arc, major plot role, diagnostic psychology or fill
intentional mysteries. Separate author truth, character knowledge/belief and
reader revelation, including timing, lies and ambiguity.

Generated details remain provisional. Capture them as proposed with exact
assistant sources through existing story_element, assertion and relationship
records as appropriate, with decisions only where current writer authority
exists. Use no separate authoritative profile document. The exchange retains
the exact prepared prose; saved proposals are not accepted canon. Normal legacy
capture also applies to intake, revisions and cancellation before displaying
the exact saved response. Do not describe a captured proposal as accepted.

Offer one profile, then wait. Support revisions and cancellation in conversation,
keeping the current complete wording unambiguous; show a full revised profile
when needed. Retain prior record versions/sources rather than rewriting history.
Do not create another character or batch automatically.

## One clear save instruction

“save this profile” accepts and saves the current complete profile without a
second approval. A narrower explicit selection saves only that identifiable
current content. Praise, choosing a trait or requesting changes alone does not
accept/save the generated profile. Clear writer facts retain ordinary authority;
selecting a specific proposition accepts only that proposition, never the whole
generated profile. A combined change and save authorizes resulting text only
when the change and selection are clear. Clarify only an unclear target or a new
conflict. If asked to keep selected content proposed, retain that status.

Before applying approval, read fresh current files, committed context and Git
state. Surface conflicting facts or intervening edits and obtain direction;
preserve existing facts, stable IDs, ownership, provenance, history, open issues
and unrelated staging. Split compound propositions for narrower approval.
Use existing current-user decisions with exact approval spans, target/result
revision refs and prior refs to accept the approved character elements,
assertions and relationships. Preserve generated sources as well as the approval
source. Supersede replaced assertions under normal authority rules; do not leave
two conflicting facts current. Save only profile content in profile records,
not explanatory rationale. The normal exact exchange still captures the reply.
This work never authorizes manuscript or other-character changes.

Use the normal exchange digest/save/checkpoint path. On partial or denied saves,
report actual saved state and what remains pending, preserve the unchanged
authorized payload where applicable, inspect before retry and avoid duplicate
records/exchanges. File save and Git checkpoint states remain separate; neither
approval nor a prepared payload proves persistence or display. Stop further
authoritative work on a failed save under entry guidance; never bypass locks or
stage unrelated work. No automatic push.

Cancellation ends profile work but does not erase historical proposed captures
or silently reject every alternative. After saving or cancelling, stop; no next
character automatically. Later retrieval uses existing source-backed character
context and inspect history, never a duplicate authoritative profile file.

Use the project language for profile prose and headings, retaining field names
and IDs. Honor explicit conversation/output language requests under existing
language guidance without silently changing project language. Host compliance
and literary quality require separate observation, not structural validation.
