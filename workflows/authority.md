# Creative authority, decisions and revisions

Judge the user's actual statement in context. A clear commitment to an
identifiable proposition establishes only that selection without another approval.
Praise, silence, speculation, hypothetical scenes, quoted dialogue and ambiguous
pronouns do not. Ask one focused clarification for unclear targets. The validator
checks references and transitions; it cannot prove a sentence's intended meaning.

Split compound ideas into independently identified propositions before selection.
selected_parts must identify only accepted parts; never promote the entire
compound statement when only one part was chosen. Unselected alternatives remain
proposed, not rejected. Every accepted idea, element, relationship and assertion
needs a current-user decision with exact span and target/result revision refs.
Bootstrap artifacts and old approving messages cannot authorize a new change.

Decisions support accept/reject/correct/revise/reverse/resolve/defer. Preserve
current user_message_ref, exact span, selected_parts, target_refs, prior_refs,
result_refs, reason, affected_refs and review_required_refs. Retain immutable prior
record versions and original capture sources. Corrections explain the error and
use the actual correcting source; never rewrite the old exchange. Reversals create
a new version restoring the specified content, rather than resetting Git history.

An explicit canon revision identifying its target and replacement is already
authorization; do not ask again unless it crosses explicit creative direction or
an unresolved conflict. Before such a change surface that conflict and require
clarification. Review preferences cannot waive this boundary. Canon changes
never authorize edits to approved manuscript text; this feature never writes it.

When replacing an assertion, preserve old/current states and mark the old fact
superseded in the same exchange. It must not remain current canon. Link supersedes
to the precise prior version, with a sourced revision decision and result refs.
Read inspect's directly_affected list to review every recorded direct dependency.
Explain that unrecorded dependencies cannot be guaranteed detected. Preserve
unrelated facts and manuscripts; linked artifacts are review references only.

Use records.checkpoint_summary with the selected project and relevant records.
Apply on_request, session_close or every_exchange as configured. Put proposals,
established decisions and open questions in the saved response and pause
agent-initiated new exploration until user direction. Current explicit direction
satisfies that pause; session closure needs no extra acknowledgment. Summary
checkpoints never delay saving or reapprove accepted facts. They are derived
views with record/source/checkpoint references, never another authority.
