# Automated POC workflow regressions

Owner decision: novice testers are out of scope, one initial user, manual testing
after POC delivery. These are automated delegated evaluations, never native-user
or novice evidence. Existing authorized task IDs are reused; each installs a NEW
disposable novel, preserving the earlier installed novel and all reports.

QUESTION repeats the earlier no-concept one-question opening. The old Icelandic
G01 saved the preference question only in conversation prose; the baseline
verifier fails explicitly in question-capture-baseline-red.txt. Current QUESTION
and PROPOSAL responses in both languages save separate open question records,
source them to the exact assistant message and retain their IDs in the session.
Earlier unanswered questions survive the topic change, and the new story idea
remains proposed rather than canon. These are scoped observed regressions; no
claim is made about every possible question or every literary judgment.

RESUME follows only after proposal persistence verification. It requests a saved
summary and pause through the installed entry. Actual public observations,
prepared driver strings and committed exchange bundles are retained separately;
verify_cases.py checks exact observed input, saved/displayed response and ordering.
verify_workflows.py checks current installed bundle bytes, linked/source-backed
question records and visible summary references. Semantic observations are
recorded in semantic-observations.md from actual final responses and saved state,
rather than inferred from authored expectations.

The source parser checks a supplied public snapshot; it does not independently
authenticate the host. All public snapshots exclude reasoning. Normal filesystem
access may be needed for Git reads and Windows hard links. Current source and
the built wheel are independently verified; older bundles are not auto-upgraded.
