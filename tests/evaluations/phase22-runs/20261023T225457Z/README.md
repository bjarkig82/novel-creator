# Phase 22 automated installed-product evaluation

This run implements T168-T171 using the owner's explicit permission to create
and drive disposable English/Icelandic chats, including fresh resumption chats.
Inputs are delegated simulations of director instructions, never native user
outcomes, human approvals, novice observations or ratings. No provider API is used.

The product chats choose their own responses and records using installed pinned
workflows. Driver files retain the submitted messages; public observations are
read through the supported app tool and omit reasoning and unrelated tool output.
The parent independently compares committed input/source labels, exact final
response (including whitespace), successful save before display and installed
bundle hashes with tests/evaluations/verify_phase22.py. Filtered verifier reports
cover only their named cases and cannot qualify the whole matrix.

## Initial gate outcomes

- Both independent novels initialize after explicit unchanged retries of sandbox
  filesystem publication failures. No lock or storage safeguard is bypassed.
- Icelandic GATE passes exact public-input, committed-response and save-order
  checks. English GATE fails exact final-response equality: public final has two
  trailing newlines absent from the saved message. Both original artifacts remain.
- English GATE_RETRY passes after a new actual delegated instruction. The failed
  original exchange is unchanged and is not counted as passing.
- The app HTML-escaped an administrative angle-bracket path placeholder in both
  create_thread prompts. Original submitted strings and public delivered strings
  remain separate. The verifier's named GATE-only transformation handles only
  that placeholder; no creative input is normalized, trimmed or rewritten.
- The verifier was developed from a failing import baseline and four green test
  methods covering multiple evidence-corruption cases. Twenty-two focused tests
  pass including existing initialization/guidance/language/authority/continuity
  tests. These checks do not award literary correctness.

## Capture sequence

CAPTURE1, CAPTURE2 and CAPTURE3 provide twenty designated compound possibilities,
ten explicit creative selections and five unanswered questions across three
sessions. Atomic extracted propositions may outnumber the designated compound
possibilities. The evaluator must map every designated possibility and selection
to actual sourced records rather than pass from aggregate counts alone.
CORRECTION changes an unaccepted possibility while retaining its prior version.
Separate fresh chats must recover saved context without supplied story answers
or prior chat transcripts. Until those checks complete, T168 remains unchecked.

before confirmed save in both languages. The separate commentary classifications
and observation-verification-CAPTURE3.json retain both failures. Their matching
final replies are not a full-boundary pass. The narrow shared-workflow repair and
current regression run are documented in ../../display-boundary-20261023.md and

do not establish complete capture, authority/continuity matrices, bilingual
